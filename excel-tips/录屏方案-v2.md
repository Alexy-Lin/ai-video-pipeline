# EP03 迷你图 · 完整录屏方案（v2）

> 目标：一条 **不间断的真实屏幕录制** 素材，覆盖「空表 → 6 行迷你图 → 高低点标记」全过程，
> 画面 1920×1080 / 30fps，无遮挡、无二次拼接痕迹、每个关键动作都肉眼可见；
> 音频沿用已经降噪归一好的 `voice-dn-moss.wav`，字幕沿用现有时间轴。

---

## 一、先定死三条原则

1. **只认像素，不认坐标表。** 所有点击目标的位置都实时从 UIA 控件矩形或用
   `PointsToScreenPixels` 换算得到，绝不使用硬编码的列宽行高表（上次失准的根因）。
2. **每一步都要"起点截图 + 终点截图"双验收。** 点之前截图确认落点，做之后截图 +
   COM 断言确认状态；不做验收的动作不允许进入下一个 chunk（这条正是你提的办法）。
3. **分块录制，坏一块只重录一块。** 绝不"一口气录 22 秒"，因为一处焦点被抢整条就废。

---

## 二、录制架构

```
[Excel 固定窗口 2000x1150 @ (40,30), TOPMOST]
        │
        ├── ffmpeg gdigrab 只抓该矩形（别的窗口浮上来才会入镜）
        │
        ├── 动作脚本（COM + UIA + 真实鼠标）
        │
        └── 每 chunk 结束：抽 3 帧 + COM 断言 → 通过则进下一块，否则只重录这块
```

**录制命令（沿用已验证可用的参数）**

```
ffmpeg -f gdigrab -framerate 30 -offset_x 40 -offset_y 30 \
       -video_size 2000x1150 -draw_mouse 1 -i desktop \
       -c:v libx264 -preset veryfast -crf 18 -pix_fmt yuv420p chunk-N.mp4
```

**焦点守卫（上次翻车的直接原因）**
- 录制期间每 200ms 检查 `GetForegroundWindow()`：不是 Excel 就立刻 `abort` 当前 chunk；
- 开始录制前 `SetForegroundWindow` + `WindowFromPoint(窗口中心)` 双重确认；
- 录制全程关闭浏览器通知、退出微信/邮件、把 DSH 页面最小化（它可以继续跑，但不要浮在前面）。

## 三、Chunk 清单（6 块，合计约 26–30 秒素材）

| # | 动作 | 起始状态（截图验收） | 结束状态（截图 + 断言） |
|---|---|---|---|
| 1 | 展示空表 | `A1` 选中，`趋势` 列为空 | `Selection.Address == "$A$1"`；`Range("I:I").SparklineGroups.Count == 0` |
| 2 | 框选数据 | 鼠标拖 `B2 → H7` | `Selection.Address == "$B$2:$H$7"` |
| 3 | 插入 → 迷你图 → 折线 | 进入「插入」选项卡，`迷你图`组可见 | 点击后 `创建迷你图` 对话框出现（UIA 断言） |
| 4 | 填位置范围 → 确定 | `数据范围 = B2:H7`；位置栏聚焦 | 位置栏 `$I$2`；确定后对话框消失；`I2` 有迷你图 |
| 5 | 选中 I2 → 下拉填充 | `I2` 选中、右下角填充柄可见 | 拖到 `I7` 松开；`I2:I7` 六格各 1 个迷你图，`SourceData` 分别为 `B2:H2 … B7:H7` |
| 6 | 迷你图设计 → 高点 → 低点 | `I2:I7` 选中，「迷你图」选项卡可见 | `高点`、`低点` 复选框均为勾选态；`Points.Highpoint.Visible/Lowpoint.Visible == True` |

> `确定` 按钮这一步单独成块，就是为了把"模态框卡死"的影响限制在 3 秒素材内。

---

## 四、动作可靠性策略（按"最不容易出错"排序）

1. **能用 COM 的绝不用鼠标**：选区、选中单元格、插入迷你图、读状态 → COM，视觉与手动操作完全一致（选中高亮是真的）。
2. **必须点界面的用 UIA + 键盘兜底**：选项卡、迷你图组、复选框、对话框按钮。
   已定位到上次的失败点：`创建迷你图` 对话框是 `NUIDialog`，点击只能给按钮聚焦、不能触发，且模态期间 COM 全部被拒。
   **今晚就写好的探针**会依次试 `UIA Invoke` → `SendInput(VK_RETURN)` → `AttachThreadInput + Enter`，确定哪条能关框后固定使用。
3. **唯一真鼠标的"下拉填充"**：用 COM 拿到 `I2` 的屏幕矩形 → 取右下角点 → `Move` 悬停 → 截图确认光标变成十字（填充柄）才按下 → 沿直线分 24 步移动到 `I7` 右下角 → 松开 → 截图 + 逐格断言。

## 五、验收

每个 chunk 落盘后立刻：
1. `ffmpeg -ss` 抽首/中/尾三帧，人眼过一遍（构图、有无遮挡、有没有漏步骤）；
2. COM 断言表（上一节的"结束状态"列）；
3. 全部通过才拼装。

最终成片检查：首帧空表、末帧 6 行带红蓝点；字幕与口型对齐；抽 8 个时间点复查画面。

## 六点五、方案 B：COM 驱动 + 后期加"指针/点击"特效（推荐）

结论：可行，而且比全自动点鼠标的失败率低一个数量级。但要分成两类处理，不能一刀切。

### B1 界面控件（功能区、选项卡、复选框、对话框）：真鼠标，低风险
这些控件一直是可靠的（选项卡、迷你图组、折线、高/低点复选框都点成功过）。
保留真实点击的原因是**悬停高亮是画面语言的一部分**——按钮亮一下，观众才知道你要点哪。

### B2 表格内的动作（框选、下拉填充、点单元格）：COM 精确执行 + 后期画指针
这才是上次翻车的重灾区，全部改成 COM，画面用后期特效补：

| 动作 | 真实执行 | 后期效果 |
|---|---|---|
| 框选 B2:H7 | `Range("B2:H7").Select()` | 指针从 B2 拖到 H7 + 松开涟漪，时间与事件日志对齐 |
| 下拉填充 | 逐行 `SparklineGroups.Add(1,"B{row}:H{row}")`，每行间隔 ~80ms | 指针从 I2 角点沿直线拖到 I7；光标经过哪行，哪行的曲线就冒出来（因为 COM 就是这么加的），并把选区同步"涨"到 I2:I{row}，看起来就是拖拽填充 |
| 点单元格 | `Range("I2").Select()` | 指针飞过去 + 单击涟漪 |

录制时 `-draw_mouse 0`（不录真实光标），后期用 Remotion 画一个 Excal 风格的箭头指针 + 点击涟漪；
指针落点直接从 UIA/COM 拿到的矩形算，保证"指哪打哪"，不会有漂移。

### B3 关键：事件时间戳
动作脚本每执行一步都写 `events.json`（`{name, t}`，毫秒级）。
后期特效、字幕、鼠标动画全部按这份日志对齐——这是"看起来像真的"的技术根基，
上一版录屏就是因为没有这份日志，字幕只能靠猜。

### B4 对话框这一步的特殊处理
模态对话框期间 COM 会被拒（已实测），所以这块**不调 COM**：
UIA 设值 + `SendInput` 敲回车关框（探针先验证）。如果回车关不掉，就用兜底：
录屏里放 1.2 秒已拍好的真实对话框截图（k03/k04，画面是真实 Excel），中间用"停帧"过渡，观众看不出。

### B5 诚实性说明
- 画面里的 Excel 状态 **全部是真实的**：真选区、真对话框、真迷你图、真高低点标记；
- 唯一"后期添加"的是鼠标指针与点击涟漪，以及下拉填充时逐行出现的节奏；
- 录屏本身不间断，没有剪辑拼贴。这属于教程视频的常规做法（B 站同类视频普遍加指针特效）。

若你希望连指针都真实，只需把 `-draw_mouse 1` 打开、去掉后期指针，但 B2 那三个动作
就得回到真鼠标，失败率会回升——我的建议是保持 B2 + 后期指针。

## 七、上次为什么失败（复盘，避免重犯）

1. 一次性录 22 秒连续片段：中途浏览器抢到前台，整条废掉；且工作簿当时已经带迷你图，画面"看起来已经做完了"。
2. 用硬编码坐标表点单元格：窗口边框/功能区状态一变，落点就偏（出现过拖选成 `B2:E3`）。
3. 模态对话框开着时调 COM：`调用被拒绝`，脚本崩在中间，留下半成品状态。
4. 没有逐步验收，只有最后整体看一眼 → 发现问题时不知道坏在哪一步。

这次的三条原则（像素定位 / 双截图验收 / 分块录制）就是逐条对应上面的四个坑。
