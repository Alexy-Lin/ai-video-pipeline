# FC27 Editor 介绍视频 · 自动化方案

> 结论先说：**Remotion 不是录屏软件，它是"用 React 渲染视频"的框架。**
> 介绍视频里"录屏"和"合成"是两件事，拆开做才能既省事又好看。
> 本仓库已经按这个思路跑通并渲染出了 `out/fc27-intro.mp4`：
> **5 个功能幕全部是 Route C（真实帧序列）**，片头/痛点/安全/结尾是纯代码动画。

---

## 1. 先分清两件事

| | 你想要的 | 合适的工具 |
|---|---|---|
| **录屏** | 把屏幕上真实发生的操作录下来 | OBS / ffmpeg / Remotion Recorder / Playwright |
| **合成** | 片头、字幕、标注、转场、缩放、批量出片 | **Remotion** |

Remotion 负责右列。左列有四种做法，下面逐条给命令。

---

## 2. 四条路线对比

| 路线 | 真实动效 | 清晰度 | 可重复性 | 工作量 | 适合 |
|---|---|---|---|---|---|
| A. ffmpeg / OBS 真实录屏 → Remotion 后期 | ★★★★★ | ★★★☆☆ | ★★☆☆☆ | 中 | 真人边讲边操作 |
| B. 截图 → Remotion 合成（**本项目**） | ★☆☆☆☆ | ★★★★★ | ★★★★★ | 低 | 产品功能片、无配音 |
| C. Playwright 帧序列 → Remotion 播放 | ★★★★☆ | ★★★★★ | ★★★★☆ | 中高 | 要鼠标/滚动动效但不想手录 |
| D. Remotion Recorder 录屏+剪辑 | ★★★★★ | ★★★★☆ | ★★★☆☆ | 低 | 带人脸讲解的教程 |

B 和 C 的关键区别：B 每个镜头只有 1 张图，靠推拉镜头造动效；C 把每个交互动作录成 30 张/秒的帧，
再逐帧播回去——**动效是真的，但完全不依赖人工录制**，重跑一次脚本就重新生成。

## 3. 路线 A：Windows 上自动化录屏

### 3.1 ffmpeg + Desktop Duplication（最清晰、可直接脚本化）

```powershell
# 整块桌面，30fps，编码成广泛兼容的 h264
ffmpeg -f gdigrab -framerate 30 -i desktop -c:v libx264 -preset veryfast -pix_fmt yuv420p -crf 18 out.mp4

# Windows 8+ 更好：ddagrab（Desktop Duplication，几乎零 CPU 开销，可指定显示器）
ffmpeg -f lavfi -i ddagrab=output_idx=0:framerate=30 -c:v libx264 -pix_fmt yuv420p -crf 18 out.mp4

# 只录某个窗口：先用 PowerShell 拿到窗口坐标，再按区域裁
ffmpeg -f gdigrab -framerate 30 -offset_x 200 -offset_y 120 -video_size 1600x900 -i desktop out.mp4
```

本机目前没装 ffmpeg。要装就下 [gyan.dev](https://www.gyan.dev/ffmpeg/builds/) 的 essentials 包，
解压后把 `bin` 加进 PATH。Remotion 自带的编码器不对外暴露，不要指望用它来录屏。

### 3.2 OBS + WebSocket（最稳，适合反复录）

OBS 28+ 自带 WebSocket（默认 `ws://127.0.0.1:4455`），用 Python 脚本控制开始/结束录制、
切场景、开摄像头：

```powershell
pip install obsws-python
```

```python
import obsws_python as obs
cli = obs.ReqClient(host="localhost", port=4455, password="你的密码")
cli.start_record()
# ... 在这里跑 Playwright 或人工操作 ...
path = cli.stop_record().output_path
```

窗口捕获（`window_capture`）比全屏干净得多，录制前把编辑器窗口固定在 1600×900。

### 3.3 Remotion Recorder（官方出的录屏+剪辑应用）

Remotion 官方有一个 **Recorder**：录屏幕 + 摄像头（最多 4 路）、自动用 whisper.cpp 生成
逐词字幕、剪静音、加转场/章节/B-roll/音乐，最后仍然用 Remotion 渲染导出。
它是 TypeScript + React 写的，主题和布局都能改。
文档：<https://www.remotion.dev/docs/recorder>

适合"我要出镜讲"，不适合"我要纯功能演示"（本项目属于后者）。

### 3.4 录完怎么进 Remotion

```tsx
import { OffthreadVideo, staticFile } from 'remotion';

<OffthreadVideo src={staticFile('rec/demo.mp4')} />
```

`<OffthreadVideo>` 是专门为渲染设计的视频组件（逐帧精确 seek，不会像 `<Video>` 那样掉帧），
配合 `startFrom` / `endAt` 裁片段，或套在一个 `<div>` 里做圆角+阴影+缩放，就是你常见的
"录屏放在一张卡片里、旁边配标题"的效果。

> 注意：真实录屏不要和 Remotion 的帧率较劲。录 30fps，合成也 30fps，最省心。

## 4. 路线 B：截图 + Remotion 合成（静态版，仍保留但未使用）

### 4.1 流水线

```
python web_app.py            # 1. 真跑起来的编辑器
    ↓
node scripts/capture.mjs     # 2. Playwright 驱动真实 UI，截 7 张 3200×1800 PNG
    ↓
public/shots/*.png           #    素材
    ↓
src/Video.tsx 的 SHOTS 表    # 3. 每个镜头：用哪张图、什么文案、多长、标注在哪
    ↓
npx remotion render ...      # 4. 逐帧渲染 → out/fc27-intro.mp4
```

### 4.2 `capture.mjs` 里几个不显然但很关键的点

1. **每个镜头重新加载页面**。编辑器有大量异步渲染，跨镜头复用页面时，
   列表会在你点下去的瞬间被 debounce 重新渲染掉。`open()` 每次都从干净状态开始。
2. **`deviceScaleFactor: 2`**。截出来是 3200×1800，视频里放到 1920×1080，
   推镜头放大 3~5% 时文字依然锐利。用 1x 截图再放大就会糊。
3. **点不进去就用原生 click 重试**。`page.click()` 会做「可见/不被遮挡/稳定」检查，
   这个应用的列表会持续重绘，于是永远不"稳定"。改成 `el.click()` + 重试 20 秒。
4. **等真实状态，别等固定时间**。`waitForFunction` 等 `#playerCount` 变成 >1000，
   比 `sleep(3000)` 可靠且更快。
5. **截图时关掉动画和光标**：`animations: 'disabled', caret: 'hide'`，避免半透明过渡帧。

### 4.3 合成侧的设计

- 手机/桌面视频都要 16:9 的"浏览器外壳"，截图才像"产品"而不是"图片"。
  见 `src/components/BrowserFrame.tsx`。
- **不做缩放**。第一版给每个镜头加了 3~5% 的缓慢推镜头（Ken Burns），实测看久了发晕，
  而且会把界面边缘的按钮裁掉。现在画面完全静止：动感只来自真实录制的操作过程，
  外加标注的淡入淡出。**结论：屏幕内容本身信息密度高，不要再加镜头运动。**
- **标注点**：`SHOTS[].callouts` 用 0~1 的相对坐标，和截图分辨率解耦。
  换一张截图不用重新算坐标，只要大致位置对。
- **时长全用帧**：30fps 下 `hold: 70` = 动作结束后停 2.3 秒。转场会重叠，总时长 = Σ镜头 − Σ转场。

### 4.4 这种做法的代价（要提前认）

- 没有鼠标移动、没有滚动、没有输入框打字的过程。观众看到的是"静止界面 + 推镜头"。
- 界面上的改动（比如真的点了「应用球员修改」）没有过程演示。
- 想补这两点 → 转到路线 C。

> 实测结论：静态版适合"参数面板/信息板"，一旦画面里有**操作过程**，静态版就显得假。
> 本项目最后把 5 个功能幕全部换成了路线 C，静态版代码留在
> `src/scenes/FeatureScene.tsx` 作为备用。

## 5. 路线 C：帧序列（要真实动效，但不手录）

核心思路：用 CDP 的 screencast 把浏览器画面按帧抓下来，存成图片序列，
再让 Remotion 当普通图片按帧播放。**不需要 ffmpeg**，也没有编码质量损失。

```js
// capture-frames.mjs 关键片段
const client = await page.context().newCDPSession(page);
let index = 0;
client.on('Page.screencastFrame', async ({ data, sessionId }) => {
  await fs.writeFile(dir + `/${String(index++).padStart(4, '0')}.jpg`, Buffer.from(data, 'base64'));
  await client.send('Page.screencastFrameAck', { sessionId });
});
await client.send('Page.startScreencast', { format: 'jpeg', quality: 92, everyNthFrame: 1 });
// ... 在这里执行 page.fill / click / mouse.wheel ...
await client.send('Page.stopScreencast');
```

Remotion 侧：

```tsx
<Sequence from={0} durationInFrames={frames}>
  <Img src={staticFile(`frames/step1/${String(frame).padStart(4, '0')}.jpg`)} />
</Sequence>
```

注意 screencast 的帧率是"有变化才推帧"，时间戳不均匀。稳妥做法是记录每帧的
`metadata.timestamp`，按时间戳重排成固定 30fps 的时间轴。

更省事的替代：`playwright` 完整包（不是 `playwright-core`）的 `recordVideo`，
它内部用 ffmpeg 编码成 webm，再进 Remotion。

### 5.1 实测：第一次只抓到 18 帧

本项目第一次跑 `capture-frames.mjs`，4 秒的动作只拿到 **18 帧**（约 6fps）——
因为 CDP 只在**页面重绘**时推帧，而这个编辑器大部分时间画面是静止的
（输完字在等接口、详情页渲染完就不动了）。

解决办法：注入一个"永远在重绘"的隐形元素，让浏览器持续产生帧。

```js
await page.addInitScript(() => {
  window.addEventListener('DOMContentLoaded', () => {
    const probe = document.createElement('div');
    probe.style.cssText =
      'position:fixed;left:0;top:0;width:1px;height:1px;pointer-events:none;z-index:2147483647;';
    document.body.appendChild(probe);
    let toggle = false;
    const tick = () => {
      toggle = !toggle;
      probe.style.backgroundColor = toggle ? 'rgba(0,0,0,0.01)' : 'rgba(0,0,0,0.02)';
      requestAnimationFrame(tick);
    };
    requestAnimationFrame(tick);
  });
});
```

加完立刻变成 **262 帧 / 4.4 秒（≈60fps）**，重采样到 30fps 得 132 帧。
颜色值几乎不可见（0.01 透明度），不会污染画面。

五条流程的实测数据（每条约 15 秒采集 + 1 秒重采样）：

| 流程 | 录到原始帧 | 重采样后 | 时长 | 素材 |
|---|---|---|---|---|
| 球员搜索 → 详情 | 239 | 120 | 4.02s | 27.0 MB |
| 球队搜索 → 阵容 | 194 | 96 | 3.22s | 22.8 MB |
| 双球队转会 | 289 | 146 | 4.87s | 39.7 MB |
| 国家队选拔 | 149 | 75 | 2.52s | 23.1 MB |
| 快捷功能 → 名单弹窗 | 196 | 98 | 3.27s | 20.3 MB |

合计 535 帧可播画面、约 133 MB 素材。**素材体积是帧序列唯一的真实成本**——
渲染时 Remotion 要把整个 `public/` 目录拷进临时目录，本项目因此多了约 2 秒启动开销。

> 更严谨的做法是 headless 模式下的 `--enable-begin-frame-control` +
> `HeadlessExperimental.beginFrame`，可以完全确定性地逐帧渲染；这里用重绘探针
> 更通用，也不依赖 headless-only 的实验接口。

### 5.2 静态标注和真实动效会打架

真实动效一上，原来给静态图设计的标注点就会挡住正在变化的内容。
本项目给 `Callout` 加了 `until` 参数（淡出帧），并改成
"出现 → 停留 → 淡出"，让标注只在需要解释的那几秒存在。

## 6. 加声音（这一步决定成片"业余"还是"能发"）

本项目用 **F5-TTS（MIT 许可）做零样本音色克隆**，逐句生成中文配音。

### 6.1 参考音频的两个陷阱

1. **F5-TTS 会把参考音频裁到 12 秒，但不会裁参考文本。**
   直接拿 25 秒录音 + 25 秒全文当参考，两边对不上，克隆出来是"另一个人"。
   做法：先裁一段 12 秒（在停顿处切），再用 whisper 转写这段，文本与音频严格对应。
2. **转写要人工校字。** whisper 把"一键"听成"一箭"、"暂存"听成"展存"。
   文本错了，音素对齐就会错，语气会飘。

### 6.2 命令

```powershell
node scripts/record-voice.mjs --open                                   # 浏览器录音
.\.venv\Scripts\python.exe scripts\prep_voice_ref.py                   # 去静音 + 归一化
.\.venv\Scripts\python.exe scripts\make_ref_clip.py                    # 裁 12s + whisper 转写
$env:HF_ENDPOINT = "https://hf-mirror.com"
.\.venv\Scripts\python.exe scripts\generate-voice.py                   # 逐句克隆
```

生成结果是 `public/audio/vo-<场景>.wav` + `src/generated/voice.json`（每句帧数）。

### 6.3 时长由配音反推

每幕时长 = `max(画面时长, 配音帧数 + 12)`。配音长就拉长镜头（最后一帧静置），
配音短就保留画面时长。所以改台词不需要手改时间轴。

### 6.4 其他可选方案

- **edge-tts**：免费、免模型，但只能选预置音色，不能克隆。
- **CosyVoice2 / IndexTTS2**：中文克隆效果也很好，但依赖链更重（pynini、onnx 等，Windows 上折腾）。
- **Remotion Recorder**：自带 whisper 字幕，适合真人出镜。

- **BGM**：务必确认授权（CC0 / 已购）。音量压到 -22 LUFS 左右，别盖过人声。

本项目当前**只有人声、没有 BGM**——留了位置，加一条 `<Audio loop>` 即可。

### 6.5 环境踩坑记录

| 现象 | 原因 | 解法 |
|---|---|---|
| pip 下载 torch 卡死 20 分钟 0 字节 | `download-r2.pytorch.org` CDN 不通 | 改 `download.pytorch.org` 主站直连，7MB/s |
| `curl -C -` 断点续传挂起 | 该 CDN 不吃 `Range: bytes=0-` | 去掉 `-C -`，直接重下 |
| `torchaudio.load` 报要 torchcodec | torchaudio ≥2.9 移除了自带解码器 | 用 soundfile monkeypatch 掉 `load`/`save` |
| `faster_whisper` 报 `metadata_errors` | PyAV 19 与 faster-whisper 1.2 的 API 不兼容 | 直接传 numpy 数组，绕开 PyAV 解码 |
| ctranslate2 报缺 `cublas64_12.dll` | 找不到 torch 的 CUDA 库 | whisper 走 CPU（12 秒音频很快） |
| `transformers` 5.x 与 F5-TTS 冲突 | 版本过新 | 本项目实测 5.20 可用 |

## 8. 踩过的坑（直接抄）

| 现象 | 原因 | 解法 |
|---|---|---|
| 渲染卡在下载 Chrome | Remotion 默认下载 Chrome Headless Shell | `--browser-executable="C:\Program Files\Google\Chrome\Application\chrome.exe"`，或环境变量 `FC27_CHROME_EXE` |
| 中文变方块 | 渲染机没有中文字体 | Windows 有微软雅黑；Linux/CI 装 `fonts-noto-cjk` |
| 视频边缘按钮被裁 | 推镜头放太多 | **不要做缩放**；屏幕内容的动感靠真实操作过程，不靠镜头运动 |
| `page.click` 超时但元素明明在 | 列表持续重绘，Playwright 等"稳定" | 用 `$eval(el => el.click())` + 重试 |
| 改完代码画面没变 | 用了缓存 bundle | 正常，Remotion 会复用；改 `src/` 会自动失效 |
| 时长算错 | 转场重叠 | 总帧数 = Σ镜头 − Σ转场（本项目 1770 − 8×15 = 1605） |
| 用 PowerShell 改 .tsx 后中文乱码 | 5.1 的 `Set-Content` 默认 ANSI | 用编辑器/文件工具写 UTF-8，别用 `Set-Content` 改含中文的源码 |

## 9. 还能往哪走

1. **竖屏版**：加一个 1080×1920 的 `<Composition>`，把浏览器外壳改成上下堆叠（B 站/抖音）。
2. **多语言**：`SHOTS` 抽成 JSON，一个语言一个文件，循环渲染。
3. **可交互预告**：用 `@remotion/player` 把同一套组件嵌进项目网页，README 里点开就能播。
4. **自动发布**：GitHub Actions 里跑 `capture.mjs` + `render`，每次发版自动出新视频。
5. **云端渲染**：Remotion Lambda，多机并行，一分钟出片。
